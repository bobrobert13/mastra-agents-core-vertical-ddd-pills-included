# ADR-009: Deterministic Security Processors as the Default Pipeline (Guardrails + Jail + HITL)

## Status
Accepted

## Context
Spec 02–05 hardened infrastructure and data; the agent request path itself was still a single processor deep: `createScopeGuard` per domain agent (root AGENTS.md gotcha #7 / hard rule). Gap-analysis §2.7 asked for the built-in Mastra guardrails "next to the scope guard", §2.6 for real human-in-the-loop. `@mastra/core@1.66.0` ships `PromptInjectionDetector`, `PIIDetector`, `TokenLimiter`, `TokenCostControl` and `ResponseCache`, plus workflow `suspend()/resume()` with storage-backed snapshots and tool-level `requireApproval`.

Three findings from the spec-06 verification pass shaped this decision (docs/specs/06-guardrails-and-hitl.md, Appendix A):

1. **The LLM detectors are not fail-open.** `PromptInjectionDetector.processInput` and `PIIDetector.processInput/processOutputResult` hard-throw on guard-model failure — unlike the scope guard, which was designed to fail open so classification outages never break legitimate traffic. Mounting them unconditionally would violate the zero-config rule ("no env var ⇒ no error") the moment a provider key went bad, and would break the keyless cold start entirely.
2. **`log` mode is not outage protection.** With `SECURITY_PROCESSORS=log` the detector still calls the guard model and still hard-throws on call failure; `log` neutralizes *false positives* only. Model availability remains the real gate; the only full off-switch is `SECURITY_PROCESSORS=off`.
3. **Approval without containment is theatre.** The file-operations domain already *mandated* path confinement in its AGENTS.md ("never accept raw user paths into `fs` calls") while all three tools passed raw paths. Asking a human to approve an arbitrary-path write outsources a security decision the machine can make deterministically.

## Decision
1. **`buildSecurityStack(scope, opts)` owns the composition** (`shared/processors/security-stack.ts`; `scope-guard.ts` unchanged, `infrastructure.ts` untouched beyond the one banner call). Order is contractual: slot 0 `createScopeGuard(scope)`, slot 1 `TokenLimiter(TOKEN_LIMIT, default 8000)`, slot 1.5 `TokenCostControl` **only when `COST_LIMIT_USD` is set** (it throws at registration without observability storage and is approximate), slot 2 `PromptInjectionDetector`, slot 3 `ResponseCache` last; output: `PIIDetector` (mask, regex-only detection types). The per-agent hard rule EXTENDS: every new Agent builds its arrays from `buildSecurityStack(scope)` — hand-assembling a bare `[scopeGuard]` array violates it.
2. **The inert rule.** The LLM detectors are constructed only when `securityMode() !== 'off' && hasAnyProviderKey()`. Zero config degrades to `[scopeGuard(inert), TokenLimiter, ResponseCache]` — deterministic work, no hard-throw paths. `SECURITY_MODEL` (fallback: `guardModel()` chain) keeps classifier cost off the primary model.
3. **ResponseCache is never given an explicit `scope`** — omission makes it auto-scope by `MASTRA_RESOURCE_ID_KEY` (per-user isolation by construction); `scope: null` (shared cache) is the leak footgun and stays unexposed. Mutating-tool agents pass `disableResponseCache: true` (cache hits replay tool calls without executing them). Multi-process sharing is the `RedisCache` follow-up riding spec 02's `REDIS_URL` convention — out of scope, pointer only.
4. **Workspace jail on by default** (`shared/tools/workspace-path.ts`): every `fs` path from `write_file` / `edit_file` / `read_file` resolves inside `WORKSPACE_ROOT` (default `./workspace`, resolved against process CWD — same quirk as `./mastra.db`). Lexical containment plus `realpath` of the deepest existing ancestor to catch symlink escapes; the residual TOCTOU race (attacker already holding write access *inside* the jail) is **accepted** for a boilerplate whose threat model is the LLM, not a co-tenant. `FILE_JAIL=off` is the escape hatch, with a loud ⚠ banner clause.
5. **HITL on both paths.** Workflow: `deep-research` ends in a `review-findings` step (`suspendSchema`/`resumeSchema`; durable LibSQL/Postgres snapshots; rejection fails the run as a decision, not a crash; `REVIEW_APPROVAL=off` for scheduled runs). Agent: `write_file`/`edit_file` carry `requireApproval: true` (pre-execution — a declined call never touches `fs`; empty-write guarantee asserted in tests); declines always pass a `reason` so the model gets the human's actual words. `approval-gate.ts` consumption helper is the seam spec 04 reuses for MCP approval conventions.
6. **Same-run tool-output scan lives in the research domain**: `web-fetch` runs `scanToolOutputForInjection` over extracted page text before it enters the loop as a tool result (Q3 option b), because the input-path detector only runs once before the agentic loop and the heavier workflow-as-processor pipeline is a documented alternative.

## Consequences
- **Positive:** defense-in-depth by construction (one enforcement point covers guard + detectors + budget + cache); zero-config boot unchanged (smoke tier proves inert-safety); durable approvals survive full process loss (Scenario 5 test); measured deterministic-slot p95 delta ≈ 0.42 ms at N=1000 vs the 10 ms PROPOSAL budget (bench artifact `tests/unit/shared/processors/security-stack.bench.test.ts`, non-CI).
- **Negative / accepted:** guard-model outages 500 requests even in `log` mode when a provider key exists (operators use `SECURITY_PROCESSORS=off`, and R1 rollout guidance is in the spec); jail is a breaking change for cloners passing absolute paths (opt-out documented + bannered); `PIIDetector` redaction on the input path is skipped from default types (LLM-only name/address/dob excluded) so streaming stays regex-only; ResponseCache is Beta — pin expectations to minor-version breakage; durable/stored agents cannot serialize a `requireToolApproval` *function* (boolean only, falling back to approving every tool call) — function form is for the regular stream/generate path.
- **Verified test surface:** unit (composition/order/inert rule/TripWire metadata shape `{ systemTokens, limit, remainingBudget?, messageCount? }`), file-operations tool tier (first tests this domain ever had), integration `hitl-suspend-resume.test.ts` (fixture HTTP server + stubbed content steps reusing the real review step; restart-resume on LibSQL file DB), live tiers behind `describe.skipIf(!hasProviderKey())`.
